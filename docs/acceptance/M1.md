# M1 acceptance criteria: Raft core

Committed before any Raft code was written or run. The mutation patches and
the runner come after the code they apply to, and are committed before they
run. `results/audit/m1/env.txt` records the commit of each run.

## Scope

In `internal/raft`, hand-written from Figure 2 of the Raft paper: leader
election with randomized timeouts, log replication, commit advancement, and
durable `currentTerm`, `votedFor` and log before any reply. Messages leave
through a `Transport` interface and durable state goes through a `Storage`
interface, with one in-memory and one file-backed implementation.

Not in M1: snapshots, membership change, a real network, a client API, and
seeded fault injection. Those belong to M2, M3 and M4.

## C. Cluster tests

These run real `Node`s against each other on a small deterministic test
network, with no real time and no goroutines. The delivery order is shuffled by
the seed. Every test checks two rules after every step: at most one leader per
term, and any two nodes that applied an index applied the same entry.

| ID | Test | Seeds | Pass criterion |
|---|---|---|---|
| C1 | `TestElectsOneLeader` | 1 to 200, on 3 and on 5 nodes | a leader within 1,000 ticks |
| C2 | `TestReplicatesToAllNodes` | 1 to 50 | 100 commands applied in the same order on all 3 nodes |
| C3 | `TestLeaderFailover` | 1 to 100 | a new leader takes over, committed entries survive, and the old leader's uncommitted entry is discarded after the partition heals |
| C4 | `TestRestartKeepsCommittedEntries` | 1 to 50 | every node is restarted in turn and no committed entry is lost |
| C5 | `TestClusterOnFileStorage` | 1 to 5 | the same, on real files with real fsyncs, after all 3 nodes restart |

## X. Each rule must have a test that can fail

Each patch breaks one rule on a throwaway copy. The named test must fail. A
mutant that survives is a gap in the tests: it gets reported and closed.

| ID | Patch | Rule it breaks | Test that must fail |
|---|---|---|---|
| X1 | `send-before-save` | persist before replying | `TestVoteIsDurableBeforeReply` |
| X2 | `forget-voted-for` | `votedFor` is durable | `TestRestartCannotVoteTwice` |
| X3 | `count-old-terms` | Figure 8: commit only current-term entries by counting | `TestLeaderDoesNotCountOldTermEntries` |
| X4 | `always-truncate` | truncate only on a real conflict | `TestDuplicateAppendDoesNotTruncate` |
| X5 | `commit-to-last-index` | follower commit stops at the last new entry | `TestFollowerCommitStopsAtLastNewEntry` |
| X6 | `no-up-to-date-check` | vote only for an up-to-date log | `TestRejectVoteForStaleLog` |
| X7 | `commit-can-decrease` | commit index never goes backwards | `TestCommitIndexNeverDecreases` |
| X8 | `fixed-timeout` | election timeouts are randomized | `TestElectionTimeoutsAreRandomized` |
| X9 | `save-after-apply` | a leader applies only what it has persisted | `TestSingleNodeAppliesOnlyAfterSave` |
